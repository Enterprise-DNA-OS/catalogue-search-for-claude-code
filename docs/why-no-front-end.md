# Why there is no front end

The catalogue manager needs to find missing products, check the agreed results, repair vocabulary and prepare a weekly review. These jobs work through the CLI and a coding agent. The database holds both the catalogue and the evidence behind each correction.

Algolia also supplies a hosted, distributed search service and website components. This project does not reproduce that infrastructure. Its English keyword engine is useful directly for a trusted operator searching and reviewing public catalogue records. Connecting it to a public website is separate work, with authentication, scaling, caching, monitoring and relevance acceptance tests.

A website search bar gives shoppers immediate results, autocomplete and interactive filters. This base has no shopper screen, mobile application, offline sync, visual merchandising editor or drag and drop. Read-only HTML reports show the manager’s work without operating a web server. The CLI does not send anything to a site.

Enterprise DNA can build the website connection and any required screens into the managed version after checking what the business uses. Keep the incumbent service running until the replacement passes the real traffic and relevance checks. There is no unconditional one-day website migration promise.
